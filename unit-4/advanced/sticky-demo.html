Sticky Section Headers

Scroll down. Each section heading sticks to the top of the viewport while its own content scrolls past, then is pushed off by the next heading. The decorative glow on the wrapper is clipped without breaking the sticky behaviour — see the comment in the CSS.

1. What sticky positioning does

A sticky element behaves like a relatively positioned element until its scroll container crosses the offset you set, at which point it sticks in place. It needs at least one inset property — top, bottom, inset-block-start, etc. — or it never sticks at all.

2. The required offset property

The offset is what tells the browser where to pin the element. Without it the element scrolls away like any normal box. Here every header uses a small top offset stored in a custom property so the value is consistent and easy to change.

3. The overflow trap (and the fix)

Any ancestor between a sticky element and its scroll container that has overflow set to hidden, scroll, or auto quietly becomes the sticky element's new scroll container. If that ancestor is not itself scrollable, the element has nowhere to stick and the feature appears broken.

The fix used on this page is overflow: clip. It clips the overflowing glow exactly like overflow: hidden would, but it does not establish a scroll container, so the sticky headers keep working. The reasoning is documented right where the fix lives in the CSS.

4. Putting it together

Sticky section headers are a small amount of CSS — position, an offset, and a background so content does not show through — but they depend entirely on no ancestor accidentally hijacking the scroll container. Clip instead of hide and the pattern is robust.
